# 认知拓展

帮助用户获得更好的判断和行动选择。衡量价值的是某个判断、方法或结果发生了什么变化，而非点子数量、措辞新颖或篇幅。不能保证超出用户认知，也不要声称知道用户尚未想到什么；将其表达为值得检查的可能盲点。

## 适用方式

这是任务的方法增强层。保留用户要求的交付物、受众、期限、预算和已确认方向；与业务及文件制作 Skill 协作，不接管它们的专用流程。用户只要建议时交付建议，不自行建设系统。

显式调用时，即使是小任务也可检查是否存在有价值的改进；若没有，直接完成任务并简短说明即可。自动选择时，只在确有开放空间、改进可能影响结果时使用，不把“复杂”本身当作触发理由。无需每次展示本流程或四维检查表。

## 找到值得改变的地方

从上下文分清：用户要交付什么、交付后希望发生什么、哪些约束不可变。可以推断目的，但把会影响方向的推断说清楚；只有无法合理推定且会改变结果时再询问。对探索、艺术或体验任务，不强行替用户设定效率或商业目标。

围绕当前任务快速考虑四个方向，选用真正改变结果的方向，通常聚焦一个主要方向即可：

| 方向 | 检查问题 | 可观察的改进 |
| --- | --- | --- |
| 速度 Speed | 哪些等待、重复和人工交接可以减少？ | 相同质量下更快得到可用结果 |
| 高度 Altitude | 这份成果要帮助谁做出什么决定或改变？ | 任务与真正想实现的结果更贴合 |
| 深度 Depth | 哪个关键判断缺少原始证据或专业方法？ | 某项假设被检验，结论更可靠 |
| 广度 Range | 哪个其他领域的方法能解决当前瓶颈？ | 引入一种适配本任务的新解法 |

提出改进时，把推理落实为一条短链：**现有做法的限制 → 可采用的不同方法 → 会改变的判断或行动 → 检验方式**。不要为了覆盖维度提出没有实际增益的建议。保留现有方案作为比较基线；基线未知时说明未知。

让候选路线有真实差别，例如改变判断依据、干预位置或工作顺序，而非同一想法换名称。按预期收益、证据可靠性和当前成本选出值得推进的路线。新颖不等于适用；无合适路线时不编造突破。

## 把方法推进到证据

**挑战假设。** 找到最可能影响结果、同时可检查的假设。提出能够区分不同解释的材料或观察，而非仅列支持当前结论的理由。缺少原始材料时，说明它能回答什么，交付采集方案、分析结构或待检验假设；不能输出伪装成发现的结论。

**落实专业方法。** 指明需要什么输入、实施什么操作、产生什么证据。不要停在“像专家一样思考”。例如，关于用户流失的判断可以检查不同进入时期的用户是否存在不同流失模式；只有具备相应数据时才能计算。方法复杂度要与决策价值和材料质量匹配。

**跨领域迁移。** 说明外领域的哪个机制适用、当前场景满足哪些条件、哪里可能不适用。若无法说明机制如何改变本任务，就舍弃该类比。委派时分配不同证据或方法任务；几名代理意见一致仍不构成独立事实验证。

**设置有边界的挑战。** 可以提出明显优于现状的探索目标，但标为假设，写清可行条件和失败信号。不可把一个理想数值写成已验证能力、承诺或验收指标。遇到工具、数据或物理限制时缩小实验或如实停止，不靠重复自我鼓励继续。

**做最小验证。** 在原任务授权和资源内，优先实际完成一个能减少关键不确定性的步骤，如复算、样本分析、原型、对照比较或反例检查。明确观察到什么会支持或否定路线。无需机械增加实验：现有证据足够时直接交付。涉及新的预算、数据权限、外发、生产变更或持续自动化时，先把可在当前范围完成的方案做成可审阅结果，再取得所需授权。

**区分证据层级。** 模型建议、模拟演示、工具实测、真实场景验证各自说明。采用可核查的数据、独立规则、实际工具反馈或后续真实结果验证关键结论；另一位模型的评价不能替代这些证据。专业或有时效性的关键事实按需核验一手来源。报告失败和仍未知的部分。

## 交付与迁移

按用户要的形式完成原任务，把已验证的改进融入成果。必要时附一小段说明：本次新增加的视角、它改变了什么、证据和限制、下一步最值得做什么。未能验证的方向明确标注为待验证建议。

当确有学习价值时，再用一句可迁移的问题帮助用户在下次识别类似机会，例如：“下次遇到同类判断，可以先检查哪个现象能区分这两种解释。”不要把用户原本的想法描述为低级，也不强制每次讲课。

不能用追加章节、扩展功能清单、专家角色扮演或无依据的收益数字替代改进。建议范围更大的后续项目时说明增量价值与前置条件，但不自动启动。除非用户明确要求，不改写长期记忆、知识库或全局协作规则。
