# 技术标质量门

## 何时读取本文件

在以下节点读取并执行对应质量门：

- 完成来源抽取后：G0—G2；
- 完成技术标初稿后：G3—G5；
- 生成 Word 后：G6；
- 声称“提交候选版”前：G7。

任何 P0 问题都阻断“提交候选版”和对外提交。内部工作稿或审查草稿可以携带已显式登记的 P0/P1，但必须标为“非提交版”并列出责任人和解决动作；提交候选版不得携带未关闭的 P0/P1。

## 缺陷级别

| 级别 | 定义 | 示例 | 处置 |
|---|---|---|---|
| P0 | 可能导致废标、虚假响应、重大合同风险或文件不可提交 | 漏掉否决项、暗标泄露投标人、无依据 SLA、错用旧评分表、文件损坏 | 立即阻断 |
| P1 | 可能明显丢分、产生交付争议或破坏评审理解 | 评分条件缺证据、条件具备写成完全满足、章节数字不一致、表格跨页不可读 | 提交前必须关闭 |
| P2 | 不影响合规但影响专业度和易读性 | 术语轻微不统一、段落过长、图表标题不佳 | 记录并择优修复 |
| P3 | 不影响合规和得分的体验优化 | 局部留白、措辞节奏、非关键图表美化 | 不阻断 |

## G0：来源与版本门

通过条件：

- 所有权威文件已进入来源版本台账；
- A/B/C 层来源均已登记 64 位 SHA-256 文件指纹；
- 招标文件、评分表、答疑、更正公告和模板均可定位到现行版本；
- 更正关系已记录，被替代条款已标为失效；
- 权威原文没有被有损摘要替代；
- 扫描件的页码、表格和标记经过人工核对；
- 项目名称、编号、采购人、包号和关键日期建立唯一标准值。

阻断项：

- 同名不同版文件无法确认；
- 评分表与招标正文冲突且无澄清；
- 缺页、OCR 错行或表格错位影响义务判断；
- 用历史项目、产品宣传或摘要反推招标要求。

## G1：路由与范围门

检查：

- 技术标、完整标、报价和 Word 文档工程的总主控是否正确；
- 技术标是否擅自新增资格、商务、报价章节；
- 完整投标任务是否已把技术章节 QA 结果交给 `bid-document-builder`；
- 报价、工期、免费服务和合同责任是否由相应责任人确认；
- 招标模板、用户要求和默认企业规范的优先级是否正确。

发现技能边界冲突时，按 `boundaries-and-routing.md` 处理，不用折中格式同时满足两个相互冲突的默认规范。

## G2：否决项、强制项与暗标门

### 否决项和强制项

建立单独清单，逐项检查：

- 技术否决项；
- ★/▲/# 等特殊标记及招标文件对标记的真实定义；
- 参数负偏离限制；
- 指定证明材料、盖章、签字或原件要求；
- 指定响应表、章节、顺序和附件位置；
- 文件格式、页数、大小、命名、分册和上传规则；
- 演示、样品、测试或现场验证要求；
- 投标有效期、工期、质保和服务期限中由技术标承载的内容。

每项都必须有“原文定位—响应位置—证据—复核人”。仅写“已检查”不算通过。

### 暗标

先以招标文件定义为准，再对所有输出载体执行检查：

- 公司名称、简称、品牌、Logo、商标、网址、邮箱、电话和地址；
- 法定代表人、员工、项目经理、客户联系人等可识别姓名；
- 过往客户、合同编号、案例截图中的公司标识；
- 产品专有名称、内部平台名或可反向识别投标人的独特术语；
- 页眉页脚、水印、母版、主题、文档属性、作者、公司和最后修改者；
- 批注、修订记录、隐藏文字、域代码、超链接地址、图片替代文本；
- 嵌入对象、附件文件名、图表数据源和图片元数据；
- PDF 属性、书签、图层和附件；
- 文件名、压缩包目录名及上传说明。

暗标清单不能机械删除所有产品名。必须依据招标文件确认哪些信息允许、哪些禁止，并保留审查记录。任何无法判断的可识别信息按 P0 待确认处理。

## G3：追溯与覆盖率门

使用追溯矩阵计算：

| 指标 | 审查草稿最低要求 | 提交候选版 |
|---|---:|---:|
| 技术需求覆盖率 | 100%，允许标记待确认 | 100%，全部复核锁定 |
| 评分项覆盖率 | 100%，允许部分满足 | 100%，满分条件均有落点 |
| 技术否决项、★/▲/# 覆盖率 | 100% | 100% |
| 必需证据覆盖率 | 明确缺口和责任人 | 100% |
| 正文承诺审批通过率 | 明确缺口和责任人 | 100% |
| 孤儿主张 | 可登记待处理 | 0 |

进一步检查：

- 每个 `requirement_id` 有且只有一个当前能力状态；
- 每个 `score_id` 的满分动作、内容、证据、形式和门槛均已拆解；
- 每个正文核心章节能反查需求或评分目标；
- 不存在只有证明材料、没有正文说明的“孤儿证据”；
- 不存在正文声称完全满足、台账却为条件具备、条件响应或待核验的冲突；
- 分档评分的高档条件没有被低档内容误判为满足。

若提供了校验脚本，先运行自动检查，再人工复核语义。自动通过不能替代对评分原文和证据适用性的判断。

## G4：事实、证据、承诺与偏离门

逐句扫描以下高风险内容：

- 产品能力、功能可用性和兼容范围；
- 案例名称、合同事实和验收结果；
- 证书、资质、专利、著作权和检测结论；
- 人员数量、履历、年限和证书；
- 并发、容量、响应时间、准确率、可用性、RPO/RTO；
- 工期、上线时间、现场到达、故障响应和解决时限；
- 免费、终身、不限次数、无条件和全部包含；
- 标准版本、法规结论和合规等级。

通过条件：

- 事实主张有可用来源和准确引用；
- 证据在有效期、产品版本、主体和项目范围上匹配；
- 第三方能力已明确归属和依赖；
- 所有量化与绝对化承诺均为 `沿用采购要求` 或 `已审批`；
- 条件具备、条件响应、定制实现、第三方依赖、不支持和不适用均有边界说明；
- 偏离对评分、报价、进度、验收和合同的影响已决策；
- 无依据主张已删除或改为不构成承诺的方案设想。

不得用“行业通常如此”“其他项目做到过”替代本项目证据。

`scan_submission.py` 对量化、绝对化和范围扩张承诺使用保守白名单：正文中的每个高风险子句必须与已关闭承诺原文等值，
同一数字在另一对象或另一子句中不能借用审批；同一句中新增的任何非空子句也必须独立获得审批，
防止通过“适用于所有环境”“不受配置约束”等同义改写扩大范围。`approval_status` 旧表只允许在
草稿模式作兼容提示，提交模式必须迁移到 V2 `confirmation_status`、证据、审批日期、冲突和处置字段。台账含
`沿用采购要求` 时，扫描必须同时读取 `source_register.json`，且只能由现行采购方权威来源白名单放行；产品资料不能替代采购原文。

## G5：一致性、污染与占位符门

### 跨章节一致性

至少核对：

- 项目名称、编号、采购人、包号、日期；
- 产品、模块、组件、角色和外部系统名称；
- 部署方式、环境数量和网络区域；
- 接口数量、数据范围、迁移范围和责任边界；
- 工期、阶段、里程碑、人员配置；
- 性能、安全、备份、容灾和 SLA 数字；
- 培训、运维、质保和免费服务范围；
- 章节号、图表号、附件号和交叉引用；
- 技术章节与商务、报价、合同偏离表的一致性。

同一概念若必须使用多个名称，应建立术语映射，不能在不同章节随意切换。

### 旧项目污染

建立当前项目标准值和“禁用词清单”，扫描：

- 旧客户、旧项目、旧采购人、旧招标编号和旧包号；
- 旧产品版本、接口系统、地区、组织和人员；
- 旧金额、工期、日期、SLA、案例和附件编号；
- 本地路径、用户名、临时文件名、生成脚本和内部代号；
- 复制内容中的页眉页脚、水印、图片文字和超链接。

自动扫描结果必须人工复核。允许出现的案例客户名称应进入白名单，并确认没有被误写成当前采购人。

### 占位符与内部信息

提交候选版中以下内容必须为 0：

- `【待确认】`、`【待补充】`、`TBD`、`TODO`、`FIXME`；
- `XX`、`XXX`、连续问号、空白下划线；
- `{{变量}}`、`<placeholder>`、模板字段和邮件合并字段；
- 内部风险级别、预计得分、责任人催办、修改说明；
- Word 批注、修订、隐藏文字和未更新域；
- 空表格行、空标题、无引用图片和断开的交叉引用。

为降低 `XX` 等误报，应维护允许词白名单，但不得直接关闭扫描。

## G6：Word 结构与逐页渲染门

生成或编辑 `.docx` 时调用 `documents` 工作流。必须同时完成结构检查和视觉检查。

### 结构检查

- 文件可正常打开，无修复提示；
- 页面尺寸、页边距、方向、分节和页眉页脚符合模板；
- 标题层级、自动编号、目录、页码和交叉引用已更新；
- 表格行列完整，重复标题行和跨页规则合理；
- 图片、图注、表注和附件清晰且编号连续；
- 字体、字号、颜色和段落格式符合招标要求；
- 暗标时文档属性、批注、修订和隐藏内容已清理；
- 导出 PDF 后页数和内容与 Word 一致。

### 逐页视觉检查

将最终版本渲染为页面图片，100% 逐页检查，不得仅抽样：

- 封面、目录、章节首页和结束页；
- 标题是否悬空，正文是否出现孤行寡行；
- 表格是否溢出、截断、挤压或跨页失去表头；
- 图片是否拉伸、模糊、遮挡或与正文不一致；
- 页眉页脚、页码和分节是否跳变；
- 目录页码、交叉引用和书签是否正确；
- 空白页是否为有意分节；
- 末页是否截断，附件是否完整。

发现问题后必须在源文档修复、重新导出并重新渲染受影响页面；若修复改变分页，应从变更页起复查到文末。

## G7：提交候选版总门

只有同时满足以下条件，才能标记为“提交候选版”：

- G0—G6 全部通过；
- P0/P1 问题为 0；
- 现行需求、评分项、强制标记和必需证据覆盖率均为 100%；
- `source_requirements.csv` 与 `technical_traceability.csv` 的需求 ID 集合完全一致，基线字段无改写；
- `待审批`/`禁止承诺`、待核验能力、未决偏离和占位符均为 0；
- 暗标禁用信息和旧项目污染为 0；
- 逐页渲染已覆盖全部页面；
- 技术标与商务、报价和合同边界完成一致性复核；
- 复核人、复核时间、文件版本和文件指纹已登记。

“提交候选版”不等于替代投标负责人最终签发。完整投标任务还须由 `bid-document-builder` 执行整本文件和提交包总检。

## QA 报告最小格式

每次候选版至少输出：

| 字段 | 内容 |
|---|---|
| 项目/包号 | 当前标准值 |
| 检查文件 | 文件名、版本、指纹 |
| 来源基线 | 招标文件、答疑、更正公告版本 |
| QA 范围 | G0—G7 中实际执行的质量门 |
| 覆盖指标 | 技术需求、评分项、强制项、证据、承诺 |
| 缺陷统计 | P0/P1/P2/P3 的发现数、关闭数、未关闭数 |
| 暗标结果 | 规则来源、扫描范围、人工复核人 |
| 污染与占位符 | 扫描结果及白名单 |
| 渲染结果 | 总页数、已检查页数、修订和复查情况 |
| 未决事项 | 工作稿/审查草稿可列；提交候选版必须为空 |
| 结论 | 工作稿、审查草稿、待复核、提交候选版 |
| 复核记录 | 责任人、日期、备注 |

## 最终停止条件

出现以下情况不要继续润色，应先升级处理：

- 权威来源版本不明；
- 否决项或暗标要求存在歧义；
- 关键能力、证据或承诺无法确认；
- 发现实质性负偏离但招标禁止负偏离；
- 技术承诺与报价、工期或合同条件冲突；
- Word 无法完整渲染或输出文件损坏；
- 用户要求“提交版”，但仍存在待确认或占位符。

停止时输出具体条款、风险、影响、责任人和最小决策问题，不要只说“材料不足”。
