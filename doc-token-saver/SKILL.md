# 大体量文档上下文预算与来源索引

本 Skill 是输入材料的预处理叠加层。它降低重复读取成本，但不把摘要当作原文替代品，也不接管方案、投标、Word 或 PPT 的内容与交付流程。

## 1. 先判断是否需要

满足任一条件时启用：

- 单个文档超过 20 页；
- 多份材料合计会显著占用上下文；
- 同一批材料将被多个下游任务反复使用；
- 预计单次任务上下文接近 150K token。

以下情况不触发：两份短文件、单纯格式转换、局部改字、已有可靠摘要可直接使用，或用户只要求处理一个明确的小范围章节。

## 2. 遵守项目级读取规则

项目 `AGENTS.md` 和用户本轮明确指令优先：

- 读取 `docs/`、`archive/` 中 20 页以内原始文件前，先询问用户。
- 20 页以上先生成不超过 2000 字的摘要并保存到 `summaries/`，后续优先引用摘要。
- 用户明确要求读取或核对原文时，完整采用原文；不得用旧摘要拒绝回读。
- 预计单次任务超过 150K token 时，先报告材料范围、拆分方案和可能遗漏，再请求确认。

## 3. 建立来源索引

摘要用于导航，必须保留可回到原文的定位信息。每份材料至少登记：

```text
【文件】原始文件名和路径
【范围】页码、章节或工作表
【用途】背景 / 需求 / 条款 / 产品能力 / 报价 / 证据
【核心结论】2-5 条
【关键事实】数字、日期、主体、标准号和原文定位
【待核验】冲突、缺失、扫描识别不确定项
【后续回读点】最终成稿前必须回到原文核对的位置
```

多个来源合并时，再生成一份跨文件索引，标明互相支持、冲突和不能互证的内容。采购文件只能证明采购要求，不能证明供应商能力。

## 4. 摘要与原文的责任边界

- 摘要可以支撑目录设计、主题聚类和初步论证。
- 招标条款、评分点、资格证据、金额、日期、性能指标、政策原文和正式引语必须回到原始定位复核。
- 不删除、不移动、不覆盖原始文件；不把“未进入摘要”解释为“原文不存在”。
- OCR 或文本提取不确定时保留疑点，不猜测修复。

## 5. 交给下游 Skill

完成索引后，根据最终交付物转交唯一主控：

- 正式售前方案：`presales-proposal-builder`；
- 完整投标文件：`bid-document-builder`；
- 技术标：`bid-technical-proposal`；
- Word 载体：`documents`；
- PPT 内容与安铂品牌：`amber-pptx-style`，PPTX 文件载体由 `Presentations` 完成；
- PDF 或表格载体：使用当前对应的 PDF、Spreadsheets Skill；
- 明确要求转换为 Markdown：`markitdown-converter`。

输入格式 Skill 与输出载体 Skill 可以按任务需要协同，不人为禁止合理的跨格式流程。结构确认、内容审批和渲染门由下游主控 Skill 决定，本 Skill 不额外增加停顿。

## 6. 完成条件

只有同时满足以下条件才算完成预处理：

- 每份来源都有路径和页码/章节定位；
- 关键数字、主体和日期未脱离来源；
- 冲突与待核验项已显式记录；
- 下游任务知道哪些内容可直接使用、哪些必须回读原文；
- 摘要文件位于项目规定的 `summaries/`，没有混入用户交付目录。
