# 智能开放审核数据构造模式

适用于档案开放鉴定、智能开放审核、档案利用权限初审、开放/限制规则匹配和多模态审核演示。目标是构造一组能让系统展示“识别规则—定位证据—给出初审结论—保留人工复核边界”的受控数据，不是把规则名称堆在一个表格里。

## 1. 两类输入必须分离

开放审核演示至少包含两类输入：

1. **开放审核规则表**：描述规则名称、规则编号和开放标志，是审核规则主数据。
2. **待审核文档**：提供需要被审核的真实或合成内容，段落和图片是主要证据单元，表格作为补充证据。

规则表不能替代待审核文档，文档清单和标准答案也不能伪装成待审核内容。只有规则要求的内容实际出现在段落、图片或表格中，才算命中。

## 2. 规则字段契约

### 2.1 最小字段：优先原样沿用用户表头

当用户提供的截图或系统样例只展示三列时，默认保留以下三列，不擅自改名或扩展运行时接口：

| 字段 | 是否必填 | 允许值/样例 | 用途 |
| --- | --- | --- | --- |
| 开放审核规则名称（暂定） | 是 | `档案销毁清册、移交清册、保管清册`；`行政法规、规章和规范性文件` | 规则的业务描述和匹配主题 |
| 规则编号（拟定） | 是 | `KZ031`；`KF001` | 规则的稳定引用键，必须唯一 |
| 开放标志 | 是 | `限制`；`开放` | 规则主数据的初始开放属性 |

截图中可直接复用的样例口径包括：`KZ028`、`KZ029`、`KZ030`、`KZ031`、`KZ032` 等限制类规则，以及 `KF001`、`KF002`、`KF003`、`KF004`、`KF005`、`KF007`、`KF008`、`KF009` 等开放类规则。具体名称和编号以用户实际表格为准，不因示例编号推造缺失规则。

### 2.2 审核增强字段：与三列主表分开

如果系统需要解释“为什么命中”，可在独立的规则说明或审核测试表中增加：`规则类别`、`匹配策略`、`关键词/表达式`、`证据要求`、`复核提示`、`规则版本`、`备注`。这些是演示辅助字段，不能未经确认写回只有三列的系统接口。

规则名称应尽量保留原表中的完整语义，不要把“行政法规、规章和规范性文件”缩写为“法规”，也不要把“机关职能、机构设置、办公地址、办公时间、联系方式、负责人姓名”拆成互不关联的多个规则，除非目标系统明确要求拆分。

## 3. 待审核文档构造

### 3.1 内容单元

- **段落（主证据）**：为每个段落生成稳定 ID，如 `P001`、`P002`；记录页码、章节标题和原文。规则相关内容应在连续段落中自然出现，避免只写一个孤立关键词。
- **图片（主证据）**：为每张图片生成稳定 ID，如 `IMG001`；记录文件名、来源/生成方式、页码、图题、OCR 摘要、可见事实、推断边界和是否作为审核证据。图片可以是扫描件、表单、批示、印章区域或业务现场示意，但生成式图片必须标注为演示模拟，不得冒充真实档案或真实现场。
- **表格（补充证据）**：为表格生成稳定 ID，如 `T001`；记录表头、关键单元格和页码。表格可以补充日期、对象、金额、状态等结构化信息，但不能让表格成为所有关键事实的唯一载体。

### 3.2 文档组合

根据演示重点，至少覆盖以下判断点中的三类：

| 判断点 | 内容设计 | 预期展示 |
| --- | --- | --- |
| 段落命中限制规则 | 正文明确出现限制类档案内容或业务事项 | 定位段落并输出“限制” |
| 图片命中限制规则 | 图片中的扫描文字、表单标题或可见内容触发规则 | 输出图片 ID、图题和审核证据 |
| 表格补充命中 | 正文含概述，表格补充对象/日期/状态 | 展示文本与表格互证 |
| 开放类命中 | 文档出现行政法规、机构信息、预算决算等开放类内容 | 输出“开放”并保留规则编号 |
| 无命中或边界项 | 内容相近但无法确认，或两条规则证据冲突 | 输出“人工复核”，不能强行开放/限制 |

不要把规则名称、预期结论或证据摘录只放进 `审核标准答案.csv`；标准答案用于验收模型，待审核文档本身必须包含可被系统发现的内容。

## 4. 推荐交付结构

```text
开放审核演示数据/
├── 说明.md
├── 开放审核规则.csv
├── 待审核文档清单.csv
├── 审核标准答案.csv
├── 待审核文档/
│   ├── DOC001_段落命中限制规则.pdf
│   ├── DOC002_图片命中限制规则.pdf
│   └── DOC003_开放类信息与表格补充.pdf
├── 图片资产/
│   └── IMG001_演示扫描件.png
└── 图片清单.csv
```

`审核标准答案.csv` 建议至少包含：`文档编号`、`规则编号`、`预期命中`、`证据类型`、`证据定位`、`证据摘录`、`期望审核结论`、`判定说明`。其中 `证据类型` 使用 `段落`、`图片`、`表格` 或 `无命中`；`期望审核结论` 使用 `开放`、`限制` 或 `人工复核`。有独立图片资产时，`图片清单.csv` 至少包含 `图片编号`、`文件名`，以便校验器交叉检查图片命中证据。

## 5. 审核标准答案与边界

标准答案不是把模型答案写死，而是定义可验证的最小事实：

- 规则编号必须能在规则表中找到，文档编号必须能在文档清单中找到。
- 命中时保留段落 ID、图片 ID 或表格 ID，并给出原文摘录或图片可见事实；不能只写“符合规则”。
- 多条规则同时命中时逐条记录，不把限制类和开放类合并成一个模糊结论。
- 图片文字无法清晰识别、证据仅有语义相似、规则之间发生冲突或文档缺页时，期望结论设为 `人工复核`。
- “开放标志=开放”是规则主数据属性，不等同于每份文档无需审核；系统仍应保留命中规则、证据定位和复核状态。

## 6. 质检要求

1. 规则三列齐全，规则编号唯一，开放标志只使用 `开放` 或 `限制`。
2. 文档清单中的每个文件确实存在；文件名、文档编号和标准答案引用保持一致。运行校验器时可通过 `--root <数据包根目录>` 执行文件存在性检查。
3. 段落、图片和表格 ID 在单份文档内稳定且不重复；图片清单中的 ID 能回指实际图片资产或文档内嵌图片。存在独立图片清单时，追加 `--image-manifest <图片清单.csv>`。
4. 标准答案中的证据定位能够在对应文档中复核；无命中行使用 `无命中`，不得伪造摘录。
5. 若文档是 PDF，使用 `pdfplumber` 检查文本层，并按需渲染检查图片是否清晰、越界或被裁切；若审核依赖图片可见信息，必须说明 OCR/图像理解边界。
6. 质检结果要区分“规则表结构通过”“证据引用通过”和“视觉内容已检查”，不能因为 CSV 可读就声称审核数据包完整可用。
