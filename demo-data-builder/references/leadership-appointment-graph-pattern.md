# 领导人事任免知识图谱模式

## 模式定位

本模式是 `demo-data-builder` 的知识图谱领域子类型，适用于领导任免、干部履历、职务变动、机构沿革、任职时段查询和前任继任推理演示。

它只在相关任务中追加到通用知识图谱流程，不替换工程项目、组织机构、档案业务或其他图谱类型。先读取 `knowledge-graph-prompt-contract.md` 锁定运行时接口，再使用本文件设计领域实体、关系和数据材料。

## 演示价值

这类数据不只是展示“识别了几个人名”，而要证明系统能处理四个业务难点：

1. 跨文件聚合同一人物的动态任职轨迹。
2. 依据有效期和沿革证据识别机构旧称、简称与现名为同一实体。
3. 区分正式任免、兼任、调任、晋升、免去与临时主持工作。
4. 使用决定日期、生效日期和免职日期回答任意时点的在任状态，并审慎推理前任继任关系。

## 四类实体契约

默认实体类型固定为 `人物`、`机构`、`事件`、`时空`。类型名称在实体配置、关系配置、提示词和示例 JSON 中必须逐字一致。

### 人物

人物是被任命、免去、调任、兼任、晋升或被安排主持工作的自然人。

识别与归一规则：

- 使用馆藏人名词典和历史职务词典锁定官方称谓，使用 LLM few-shot 判断“某某同志”“周主任”等边界模糊指代。
- 规范姓名、同志称谓、职务称谓和明确曾用名归入同一人物节点；同名人物联合任职机构、职务、任职时段和审批档号消歧。
- 有内部人员 ID 时优先作为实体配置中的稳定主键；默认运行时提示词仍以 `name` 作为节点唯一标识。
- 影像档案存在时可增加人脸嵌入索引，但没有合法、已核验图片时不构造身份判断。

人物扩展属性建议：

| 属性 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| 规范姓名 | 字符串 | 必填 | 以组织正式记录为准 |
| 曾用名/别名列表 | 字符串列表 | 可空 | 用于同义词检索和跨文件聚合 |
| 生卒年份 | 日期区间 | 可空 | 不得为真实人物猜测补齐 |
| 职务任免历史 | 结构化列表 | 核心属性 | 每条含职务名称、任职机构、职务级别、任职起始日期、免职日期、任免依据档号 |
| 主要活动履历 | 文本 | 可空 | 用于人物消歧和专题展示 |
| 关联档案标识符列表 | 标识符列表 | 系统维护 | 聚合涉及该人物的档案 |

职务默认不是第五类实体。它进入人物的 `职务任免历史` 和事件属性；只有用户或目标系统明确要求职务本体时，才允许扩展实体类型，并同步修改所有配置和提示词校验参数。

### 机构

机构包括任职机构、决定机构、主管机构及内部部门。

机构配置必须包含：标准名称、简称列表、历史名称序列、名称有效时间、机构代码、上下级隶属、合并撤销信息和归一依据。

同一实体合并条件：

- 文件明确表述为“更名”，且机构代码、统一标识或档案全宗保持不变。
- 人员编制、职责和档案连续承接，能够证明只是名称变化。
- 标准全称与简称差异，且地域、主管机构和时间范围一致。

不得合并的情况：

- 合并新设形成新的法人或机构。
- 撤销后职责并入另一机构。
- 名称相同但地域、主管单位、机构代码或有效期不同。
- 只有语义相似或跨文件共现，没有沿革证据。

历史名称处理规则：

1. 为每个名称记录 `valid_from`、`valid_to` 和原文写法。
2. 文书日期位于名称有效期内时，归一到 `canonical_id` 并保留原文名称。
3. 旧称出现在失效日期之后时仍可归一，但要标记“名称时态冲突”，不能静默纠正。
4. 上级机构和内设部门分别建节点，以 `隶属于` 关系连接，不粘成一个长实体。

### 事件

事件以人事任免事件为主，同时容纳机构更名和临时工作安排等直接影响履历判断的事件。

人事任免事件属性：

| 属性 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| 任免人员 | 人物引用 | 必填 | 指向人物节点 |
| 新职务 | 字符串 | 必填 | 从历史职务词典规范化匹配 |
| 原职务 | 字符串 | 首次任职可空 | 不能用后续履历倒推 |
| 任免类型 | 枚举 | 必填 | 任命、免去、调任、兼任、晋升 |
| 决定机构 | 机构引用 | 必填 | 对接机构沿革知识库 |
| 决定日期 | 公历日期 | 必填 | 标准化为 YYYY-MM-DD |
| 生效日期 | 公历日期 | 可空 | 与决定日期分别保存 |
| 审批文件档号 | 标识符列表 | 必填 | 支持证据追溯 |
| 保密级别 | 枚举 | 必填 | 取值沿用用户或系统配置，不补造缺失枚举 |

事件识别边界：

- 主持工作不等于正式任命，二者必须使用不同事件子类和不同履历处理规则。
- 任命、免去、调任、兼任、晋升等明示动词可形成正式任免事件。
- “主持工作”“负责日常工作”“代行职责”只形成工作安排事件，除非同一文件明确使用正式任命动词并给出正式职务。
- 按人物、新职务、任职机构、决定日期和审批档号做跨文件事件去重。
- 一份决定同时免去前任并任命继任者时，可以保留一个复合任免事件，也可以按目标系统要求拆成两个事件；无论采用哪种方式，标准答案和提示词示例必须一致。

### 时空

时空实体统一承载决定日期、生效日期、任职时段和明确地点，使用 `subtype=时间/地点` 区分。

- 中文日期、数字日期和历史纪年转换为公历标准值，并保留原始表达和精度。
- 决定日期和生效日期分别建关系；时点任职查询以生效日期和免职日期为准。
- 相对日期必须依赖原文锚点计算，无法唯一确定时标记待确认。
- 历史地名按有效时间映射至标准行政区划，并保留历史名称。
- 任职时段重叠通常表示兼任；同机构同职务前后时段顺接可作为继任推理候选。

## 推荐关系

默认从以下关系中选择，不要求每个项目全部使用：

| 关系 | 起点 | 终点 | 使用条件 |
| --- | --- | --- | --- |
| 任免对象 | 人物 | 事件 | 原文明示该人物为正式任免对象 |
| 工作安排对象 | 人物 | 事件 | 只用于主持工作等非正式安排 |
| 决定机构 | 事件 | 机构 | 原文明示作出决定或通知的机构 |
| 任职机构 | 事件 | 机构 | 新职务所在机构 |
| 沿革机构 | 事件 | 机构 | 更名事件指向归一后的同一机构节点 |
| 决定时间 | 事件 | 时空 | 决定形成日期 |
| 生效时间 | 事件 | 时空 | 任免或更名实际生效日期 |
| 发生地点 | 事件 | 时空 | 原文明示的行政区域 |
| 任职于 | 人物 | 机构 | 仅正式任免写入，扩展标准答案可附职务属性 |
| 隶属于 | 机构 | 机构 | 明确的上下级机构关系 |
| 继任 | 人物 | 人物 | 跨文件规则推理关系，和直接抽取关系分开保存 |

运行时 JSON 不增加职务、档号、别名或置信度字段。丰富属性放在实体配置、标准答案或导入表中，避免污染 `knowledge-graph-prompt-contract.md` 定义的系统接口。

## 来源材料构造

生成 4-6 份共享同一人物和机构世界的 PDF，将履历分散在不同文件中。推荐组合：

1. 早期任职与晋升决定。
2. 兼任决定和机构第一次更名通知。
3. 跨机构调任决定。
4. 主持工作通知与正式任命决定。
5. 机构再次更名及后续领导调整决定。

每份材料同时包含正文和结构化表格，并重复出现规范姓名、机构原文名称、决定日期、生效日期和档号。

至少设置三个判断点：

- 旧称与现名应归一为同一机构，但合并新设不能归一。
- 主持工作不能写成正式任命。
- 决定日期与生效日期不同，两个日期之间的在任状态不能提前切换。

需要展示继任关系时，至少增加一名前任和一名继任者。推理依据必须包含同一归一机构、同一规范职务以及明确的前后任时段，不能仅凭人物在同一文件共现。

## 默认交付物

- 四类实体配置 JSON/CSV。
- 关系类型配置。
- 人物别名词典、机构历史沿革词典、历史职务词典、时间地点规范化词典。
- 标准答案节点、直接关系和推理关系，推理关系单独保存。
- Neo4j 或目标系统导入表。
- 运行时图谱抽取提示词。
- 4-6 份来源档案 PDF。
- 字段质量评估、现场演示问答和质检结论。

## 质量门槛

交付前逐项检查：

1. 实体类型只有人物、机构、事件、时空，除非用户明确批准扩展。
2. 机构沿革词典同时包含标准名称、旧称、有效期、机构代码和同一实体依据。
3. 所有正式任职记录都有生效起点和任免依据档号；未知值明确标记，不猜测。
4. 工作安排事件没有进入正式职务任免历史。
5. 决定日期和生效日期分别保存；任职时点查询结果符合生效规则。
6. 直接关系的 evidence 能逐字命中来源 PDF；继任等推理关系单独标记推理依据。
7. 抽取提示词运行：

```powershell
python scripts/validate_graph_prompt.py <提示词.md> --types 人物 机构 事件 时空
```

8. 所有 PDF 完成文本层提取和逐页视觉检查，不存在中文缺字、表格越界或内容截断。
9. 真实人物或真实机构先联网核验；业务目标不要求真实事实时，优先使用虚构但合理的数据并在每份材料标明合成边界。
