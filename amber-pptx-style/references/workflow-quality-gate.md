# 安铂 PPT 工作流与质量门

本文件把内容、视觉和载体 QA 串成一个可验收流程。它不重复 `Presentations` 的实现 API。

## 1. 主控边界

- 售前业务判断：`presales-consultant-persona`；
- 正式方案内容：`presales-proposal-builder`；
- 投标评分、承诺与证据：`bid-document-builder` / `bid-technical-proposal`；
- 安铂逐页内容、品牌和视觉语义：本 Skill；
- PPTX 文件读写、模板继承、实现、渲染和溢出检查：当前 `Presentations` Skill。

本 Skill 不修改上游已确认的金额、承诺、产品边界和证据等级。

## 2. 生成前硬门

新建或重大重构时，先完成并提交完整逐页内容稿。只有 `approval_status` 为 `confirmed` 或 `waived_by_user` 时，才允许生成内容锁和版式计划。

以下变化使原版本 `superseded`，必须重新确认：新增、删除、合并页面，或改变核心结论、关键论据、受众和决策目标。错字、非实质措辞、配色、字体和局部排版不重新确认。

## 3. 动态版式门

每页记录：内容信号、版式家族、具体变体、视觉主角、组件、密度和选择理由。存在以下情况时返工：

- 阶段、层级、比较、数据、场景或风险关系被退化成普通 bullet；
- 连续三页使用同一构图且内容关系并不要求；
- 版式理由只是“模板里有”；
- 高密度页没有证据、解释和决策含义；
- 为追求版式数量而牺牲内容关系。

标题长度、正文行数和版式数量只是启发式，客户模板和可读性优先。

## 4. 视觉完成度

- 每页一个主视觉焦点，信息层级清楚；
- 关系用合适的图、表、流程、架构或矩阵表达；
- 中英双语仅在受众需要时使用；
- 图标和图片承担语义，不设置数量配额；
- 无 emoji、空白占位、假截图和示例数据；
- 不连续堆叠 UI 卡片，不用装饰替代分析。

## 5. 实现与来源

生成本地 PPTX 时完整遵循当前 `Presentations` Skill：在可写临时目录实现，使用其指定工具链，按其要求记录外部图片和非平凡外部主张的来源。客户模板或既有 PPTX 必须走模板继承路线，不重建母版来“近似复刻”。

## 6. 全页渲染验收

交付前必须：

1. 渲染全部最终页；
2. 逐页全尺寸检查，不以联系表代替；
3. 运行溢出检查；
4. 修复重叠、裁切、换行、断裂连接线、占位符、页脚和图表数据问题；
5. 再次渲染受影响页面并复核；
6. 检查全稿节奏、品牌一致性和内容连贯性。

无法完成渲染时不得声称交付完成。明确报告阻塞原因、未检查页面和下一步。

## 7. 示例残留扫描

交付前搜索并核对：

- 历史客户、项目和公司名称；
- 固定日期、金额、百分比、人员数、客户数和软著数；
- `【待填真实数据】`、`【待补充】` 和其他占位符；
- “根据 Skill”“参考知识库”“内部映射”等过程性词语；
- 未确认的一期/二期、本期或绝对承诺。

发现一项就回到来源或已确认内容修正，不能把扫描结果只写在交付说明里。

## 8. 最终判定

只有内容与已确认版本一致、来源可追溯、版式表达真实关系、全部页面完成渲染检查且无严重问题时，才能称为交付完成。文件能够打开不等于通过验收。
