# 安铂 PPT 图示选型规则

图示只在能显著降低理解成本时使用。先识别内容关系，再选择实现路线；具体 API 遵循当前 `Presentations` Skill。

## 1. 实现路线

- 简单流程、分层、时间线和少量节点关系：使用原生 PowerPoint 形状，先创建连接线，再创建节点，使连线位于节点后方。
- 复杂拓扑、网络或多层关系：使用 Graphviz 等关系图工具生成清晰结构，再按 `Presentations` 要求嵌入并检查。
- 高审美、说明性或科学信息图：使用图像生成；关键文字和可编辑数据仍应留在 PowerPoint 原生对象中。
- 只是并列两三项：不必画图，使用清晰排版即可。

## 2. 内容关系与图示

| 内容关系 | 推荐图示 | 必须回答 |
|---|---|---|
| 先后顺序 | 流程、路线图、时间线 | 输入、输出、责任人与关键节点是什么？ |
| 上下层级 | 分层架构、泳道 | 每层职责和跨层关系是什么？ |
| 组织分解 | 树、问题树、能力树 | 父子关系是否互斥且穷尽？ |
| 循环治理 | 闭环 | 反馈如何回到下一轮？ |
| 多方协同 | 泳道、RACI | 谁发起、谁处理、谁审批？ |
| 两类比较 | 矩阵、Before/After | 比较维度和判断标准是什么？ |
| 优先级 | 四象限、价值-难度矩阵 | 坐标口径和阈值是什么？ |
| 转化或筛选 | 漏斗 | 每阶段数量和淘汰逻辑是什么？ |

## 3. 安铂视觉

- 主路径使用结构蓝，关键节点或风险闸门使用焦点橙。
- 节点文字短而完整，详细解释移到旁注、证据块或讲者备注。
- 连接线不穿过节点或标签；交叉不可避免时调整结构，而不是缩小字号。
- 架构图的层、域、边界、接口和安全/标准纵向体系必须能被区分。
- 不用同权重卡片冒充架构，不用装饰箭头制造虚假的因果关系。

## 4. 四层架构专项检查

采用“基础设施层—多模态数据底座—支撑组件层—业务应用层”时，逐项检查：

- 网络域没有被误写成业务应用；
- 支撑组件没有跨层放入业务应用；
- 业务应用名称与当前方案标题层级一致；
- 卡片文字没有溢出，连线没有跨层误导；
- 安全、标准和运维体系的纵向作用范围表达清楚。

## 5. QA

- 图示表达的关系与正文、已确认内容稿一致；
- 所有节点、箭头、图例和边界都有业务含义；
- 全页渲染后标签可读、连线清楚、对象未越界；
- 复杂图示在缩略图下仍能看出主要结构，在全尺寸下能读完细节；
- 没有历史案例名称、示例数字或未经证实的能力残留。
