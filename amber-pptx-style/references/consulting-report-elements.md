# 安铂 PPT 咨询报告元素库

本文件吸收 CyberPPT 中适合安铂使用的咨询报告式设计元素。只迁移“结构、组件、图表语义、质检方法”，不迁移 CyberPPT 的赛博配色、8 套视觉样张强制选择、逐页 ImageGen 蓝图强制流程或整页图片化做法。

使用时机：用户确认逐页主要内容稿后，在动态版式规划阶段读取本文件。它回答“这一页除了标题和卡片，还应有哪些咨询报告元素”。

## 1. 迁移边界

| 可吸收 | Amber 改造方式 | 不吸收 |
|---|---|---|
| 高密度页面的信息区、主图/侧栏比例、证据块、注释、图例、微图表、SO WHAT | 统一改成安铂蓝橙、浅灰蓝底、Slate 正文、可编辑原生对象 | CyberPPT 红/绿/紫/米色等默认色板 |
| 咨询报告的结论标题、证据链、caveat、业务含义 | 与售前内容确认和 slide_content_lock 结合 | 未经确认直接进入视觉制作 |
| 图表语义：矩阵、趋势、桥图、漏斗、路线图、桑基/流线、热力表 | 简单图表原生重建；复杂曲线/流线用 SVG path 或 custom geometry，文字仍原生可编辑 | 用整页截图或蓝图截图当最终 PPT |
| QA 门：标签避让、空间锚点、容器边界、表格语义字号、表格密度 | 加入 Amber 交付前质量检查 | 过度的逐页 1:1 测量流程作为默认要求 |

## 2. 咨询报告页面表面系统

高质量咨询页不是“白底 + 卡片”，而是由多个表面层共同建立秩序。Amber 默认使用以下表面：

| 表面层 | 作用 | Amber 表达 |
|---|---|---|
| 页面底 | 控制整体明暗和留白 | `#F8FAFC` 或深蓝章节底 |
| 主分析区 | 承载图表、架构、矩阵或流程 | 白色/浅蓝灰面板，细边框，少阴影 |
| 证据侧栏 | 放证据、caveat、来源、解读 | 右侧 22%-30% 宽，浅蓝灰底或白底 |
| SO WHAT 区 | 提炼管理含义、行动建议 | 底部或右下，橙色短线/深蓝标题，不做装饰口号 |
| 注释层 | 图表标签、来源、口径、风险提示 | 小字号但清晰，靠近对应对象，不堆到页脚 |
| 品牌锚点 | 保持安铂识别 | 小面积深蓝结构条、橙色节点、页码徽章或侧栏色线 |

规则：如果一页需要承载证据、图表和结论，优先采用“主分析区 + 证据侧栏 + SO WHAT”的三层表面，不要平均分成三到四张卡片。

## 3. 可复用咨询组件

### 3.1 结论标题 + 证据副标题

适用：所有咨询型内容页。

要求：标题是一句可辩护判断；副标题说明判断依据、范围或 caveat。不要写“建设背景”“功能介绍”这种栏目名。

### 3.2 Evidence Block 证据块

适用：需要说明事实依据、来源状态、风险边界的页面。

结构：`证据标签 E01 / 证据标题 / 1-2 行解释 / 来源或 caveat`。

Amber 表达：左侧橙色短线或小徽章，白底细边框，正文 Slate 灰。证据块不超过 4 个；超过 4 个改成证据表或附录页。

### 3.3 Insight Sidebar 洞察侧栏

适用：主图较复杂，需要右侧解释“读图方式”和“管理含义”的页面。

结构：`关键发现 / 风险边界 / 决策含义`。侧栏宽度通常为页面 22%-30%，不能抢主图视觉权重。

### 3.4 SO WHAT / WHY IT MATTERS 结论条

适用：图表页、架构页、流程页、对比页。

结构：`SO WHAT 标签 + 一句话业务含义 + 下一步动作或决策指向`。

规则：SO WHAT 不是重复标题，也不是口号。它必须回答“所以客户应该怎么判断”。

### 3.5 Caveat / Source Note 注释与来源

适用：涉及数据、政策、评分点、客户材料、行业假设的页面。

规则：来源靠近使用该证据的图表或表格。不能把所有来源塞到最底部导致无法对应；不能把未知数据写成确定事实。

### 3.6 Microchart 微图表

适用：侧栏或证据块中需要表达轻量趋势、占比、结构差异。

常用：sparkline、小条形、迷你堆叠条、状态点、进度条、评级点阵。微图表必须有标签或解释，不单独当装饰。

### 3.7 KPI Strip 指标条

适用：运营复盘、成效证明、项目价值页。

结构：3-5 个关键指标横向排列，每个指标包含“大数字 + 单位 + 口径/含义”。如无真实数据，不得伪造，可改为“价值假设清单”。

### 3.8 Annotated Chart 标注型图表

适用：趋势、对比、结构变化。

要求：关键节点直接标注，少依赖图例；图表旁必须有一句解读。图表不是装饰，必须说明“数字证明了什么”。

### 3.9 Decision Box 决策框

适用：领导汇报、立项、结尾页。

结构：`建议结论 / 关键理由 / 风险控制 / 需要拍板事项`。不要用“谢谢”替代决策收束。

## 4. 咨询图表与图示选择

| 内容问题 | 首选表达 | 适用说明 | 避免 |
|---|---|---|---|
| 规模、占比、构成 | 条形图、堆叠条、树状分组、KPI Strip | 让数字成为主角，配口径说明 | 把数字埋进正文 |
| 趋势变化 | 折线、面积、斜率图、阶段趋势带 | 直接标注关键拐点和阶段 | 只有线没有解释 |
| 投入产出、差距修复 | Waterfall / Value Bridge | 适合解释“从现状到目标”的贡献项 | 普通三卡片收益 |
| 多维对比 | 2x2 矩阵、热力矩阵、评分矩阵、雷达图 | 适合方案对比、能力成熟度、评分响应 | 两栏长文字 |
| 路径推进 | Roadmap、Gantt、阶段门、波次图 | 适合实施计划、迁移路径、分期建设 | 编号列表 |
| 业务流转 | 泳道、Journey、闭环流程、SIPOC | 适合跨角色、跨系统、跨部门流程 | 横向箭头硬串 |
| 系统组成 | 分层架构、能力地图、生态图、数据流 | 适合平台、数据、应用、安全体系 | 功能九宫格 |
| 因果诊断 | Issue Tree、鱼骨、漏斗、问题链 | 适合痛点、风险、必要性论证 | 三个痛点卡片 |
| 证据映射 | 条款-响应-证据表、评分索引、政策映射矩阵 | 适合投标、标准、政策依据 | 摘抄大段原文 |
| 复杂迁移/流向 | 桑基、流线、带状迁移、弧线流程 | 只在确有流量、流向、迁移语义时使用；文字和标签必须原生可编辑 | 用矩形条冒充流线 |

## 5. 表格与矩阵的专业化规则

表格不是把文字塞进格子，而是呈现映射关系、决策比较和证据链。

- 表头要短，正文要能读；表格正文、行动项、风险项、解释句、建议句不得压成微标签。
- 三列证据表推荐：`评分点/条款`、`安铂响应`、`证据或交付物`。
- 风险表推荐：`风险场景`、`影响`、`控制措施`、`责任/阶段`。
- 决策矩阵推荐：`选项`、`价值`、`成本/复杂度`、`风险`、`建议`。
- 热力矩阵必须有图例；颜色只用安铂蓝阶、橙色高亮和灰阶，不引入红绿灯式强烈杂色，除非用户明确要求风险红绿灯。
- 表格过密时优先拆成“主表 + 右侧解读”，不要一味缩字。

## 6. 图标与视觉资产策略

CyberPPT 的大规模 SVG 图标库可以继续作为 Amber 的图标来源，但图标风格必须收敛：

- 默认使用 `tabler-outline`，统一改为安铂蓝或 Slate 灰；关键节点可用安铂橙。
- 同一页不混用 filled、outline、duotone 三种风格。
- 图标只用于标识类别、动作或状态；架构、表格、图表页不强塞装饰图标。
- 产品截图、客户 Logo、真实场景图片优先于抽象插图。没有真实素材时，用结构化面板替代，不留空白图片框。

## 7. 高密度页面最低组件标准

当 `density=high` 或页面角色是 Evidence Page、Solution Architecture、Decision Page、投标响应、数据分析页时，至少满足以下 4 项中的 3 项：

1. 主图、表格、矩阵、架构或流程占据页面主体区域；
2. 至少 2 个证据块或注释；
3. 有 SO WHAT / 决策含义 / 下一步动作；
4. 有来源、口径、caveat 或证据 ID；
5. 有直接标签、图例、微图表或局部放大。

如果做不到，说明内容稿本身不够密，应回到内容阶段补证据、拆页或降低页面承诺。

## 8. 生成后 QA 加严项

从 CyberPPT 迁移以下检查，但按 Amber 默认流程降级执行：

- 标签避让：中心图、流程图、架构图、矩阵图、时间线、路径图中，文字不能压住图标、节点、箭头、曲线或边框。
- 空间锚点：主图、侧栏、SO WHAT、关键数字的位置关系要稳定，不得因为可编辑性把视觉语义改掉。
- 容器边界：文字、数字、项目符号、图表标签和来源必须留在所属卡片、面板、表格单元格、SO WHAT 或图表区内。
- 连续文本流：一句话被拆分成多个文本框时，不能出现异常空格、断句、基线错位或阅读顺序错误。
- 表格语义字号：表格正文、行动项、风险项、建议句要按正文可读层级处理，不得当微标签。
- 表格密度：行高、列宽、字号和换行要共同填满信息结构，不能空洞，也不能挤压。
- 图表语义：流线、桑基、迁移、弧线和异形图表不能降级为普通矩形条；折线、柱状、坐标轴、标签、表格和 SO WHAT 默认必须原生可编辑。
