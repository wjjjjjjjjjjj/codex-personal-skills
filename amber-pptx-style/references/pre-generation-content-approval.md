# 安铂 PPT 生成前主要内容确认门

本文件定义新建或重大重构 PPT 时的用户确认机制。目标是先确认“讲什么、凭什么讲、希望听众接受什么判断”，再决定页面怎么呈现。

## 1. 适用与豁免

以下场景必须输出完整内容稿并等待确认：新建 PPT、重构故事线、售前方案、客户/领导汇报、投标演示和产品介绍。

仅改字、换图、局部排版、修复渲染问题不触发整套内容确认。用户明确提供已确认的逐页大纲，并明确要求直接生成时，可记录 `approval_status: waived_by_user` 后继续。

## 2. 必须输出的格式

```markdown
# PPT 主要内容稿（待确认）

## 全稿定位
- 汇报对象：
- 汇报目标：
- 希望推动的决策/行动：
- 核心结论：
- 建议页数：
- 已知事实：
- 行业假设：
- 待补充信息：

## 第 N 页｜[结论型标题]
**本页主要说明的问题：**

**对应问题解释：**

**阐述的论据：**
1. [论据]（来源：E01 / 用户输入 / 行业假设 / 待确认）

**本页结论：**

**与前后页的关系：**

**建议视觉表达：**
```

“主要说明的问题、对应问题解释、阐述的论据”是不可省略字段。论据不足时必须写明缺口，不能编造事实补齐。

## 3. 审批状态机

| 状态 | 含义 | 允许动作 |
|---|---|---|
| `draft` | 内容稿正在形成 | 修订内容，不生成 PPT |
| `pending` | 已完整提交用户 | 等待确认，不生成 PPT |
| `confirmed` | 用户明确确认当前版本 | 内容锁定、版式规划、生成 PPT |
| `waived_by_user` | 用户明确要求免确认 | 内容锁定、版式规划、生成 PPT |
| `superseded` | 确认后发生重大内容变化 | 重新提交完整内容稿 |

确认前禁止：创建 PPTX、制作页面代码、生成正式图片资产、把版式草案当作已批准内容。

## 4. 修改与重新确认

- 用户修改单页时，检查前后页是否仍可承接；受影响页面一并更新。
- 新增、删除、合并页面，或改变核心结论、关键论据、受众和决策目标时，版本号递增并重新确认。
- 仅调整字体、配色、图标或已确认内容的非实质性措辞，不需要重新确认。

## 5. 面向用户的结束语

内容稿末尾必须明确写：

> 请确认这份完整主要内容稿；确认前我不会开始生成 PPT。若需调整，请直接指出页码和修改方向。
