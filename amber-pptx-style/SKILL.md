# 安铂（amberdata）企业级 PPT 生产规范

## 1. 适用范围与优先级

本 Skill 负责把已核验的售前或汇报内容组织成可决策的逐页叙事，并定义安铂蓝橙视觉与验收标准。它是内容与品牌叠加层，不自行维护第二套 PPTX 生成 API；本地 PowerPoint 的读写、模板继承、实现、渲染和溢出检查统一遵循当前 `Presentations` Skill。

### 1.1 必须执行完整流程的情况

- 新建 PPT；
- 对既有 PPT 进行重大故事线、页面结构或核心论点重构；
- 售前解决方案、客户汇报、领导汇报、投标演示、产品介绍。

### 1.2 不执行整套内容确认的情况

- 仅改错别字、替换一张图片、调整一页布局、修复渲染问题；
- 用户明确提供已确认的逐页内容稿，并明确要求“无需再次确认，直接生成”；
- 用户明确指定不使用安铂规范。此时退出本 skill 的视觉规则，改用用户指定规范。

### 1.3 规则优先级

1. 用户明确指定的客户 VI、既有模板或非安铂风格；
2. 用户确认的逐页主要内容稿；
3. 当前任务类型和材料事实；
4. 本 skill 的动态版式和品牌规则；
5. 示例和模板代码。

示例永远不能覆盖用户材料，也不能把“合规保管到数据资产运营”等历史示例结论带入不相关项目。

### 1.4 唯一主控路由

- 安铂日常售前、客户、领导或投标答辩 PPT：本 Skill 主控内容确认与品牌，`Presentations` 主控文件载体。
- 用户明确点名 CyberPPT、8 套样张或逐页 ImageGen：由 CyberPPT 单独主控，本 Skill 退出。
- 用户明确点名 ppt-master 或 SVG 多角色流水线：由 ppt-master 单独主控，本 Skill 退出。
- 客户提供模板、参考 PPTX 或既有 PPTX：`Presentations` 的模板继承流程优先；除非用户仍要求安铂内容方法，否则本 Skill 不覆盖客户视觉。
- 只有客户颜色规范、没有模板，且用户要求保留安铂版式方法：可以进入“客户 VI 换肤”模式，但不得擅自混入安铂品牌标识。
- 通用、非安铂 PPT：`Presentations` 主控。

## 2. 强制生产工作流

```text
任务分类 → 事实/证据边界 → SCR 故事线 → 完整逐页主要内容稿
→ 用户确认（停）→ 内容锁定 → 动态版式规划 → PPT 生成 → 渲染质检 → 交付
```

### 阶段 A：任务分类与事实边界

先判断是领导决策、客户售前、产品演示、投标答辩、培训宣讲还是既有 PPT 局部修改。客户名称、数字、金额、日期、政策条款不得编造。无法证实的信息标记为“行业假设”或 `【待补充】`。

内容事实由对应业务 Skill 主控：售前判断叠加 `presales-consultant-persona`；方案内容由 `presales-proposal-builder` 主控；投标评分点、技术承诺和证据由 `bid-document-builder` / `bid-technical-proposal` 主控。本 Skill 只把已确认内容转换为逐页论点、内容锁和视觉计划，不改变承诺、数字或证据等级。

售前/汇报/投标任务必须阅读：

- `references/consulting-logic-and-content-lock.md`
- `references/pre-generation-content-approval.md`

### 阶段 B：完整逐页主要内容稿（生成前硬门）

新建或重大重构 PPT 时，必须先输出一份完整的《PPT 主要内容稿（待确认）》。不得只展示前几页，不得同时开始生成 PPTX、图片或代码。

每页必须包含：

1. 本页主要说明的问题；
2. 对应问题解释；
3. 阐述的论据及来源状态；
4. 本页结论；
5. 与前后页的承接关系；
6. 建议视觉表达方向（只写方向，不进入制作）。

内容稿输出后，明确说明“等待确认，当前不生成 PPT”。只有用户明确确认（如“确认”“按此生成”）或明确豁免确认，才能进入下一阶段。

用户提出内容修改时，更新受影响页面及其前后承接。新增、删除、合并页面，或改变核心结论、关键论据、受众、决策目标时，形成新版本并再次请求确认；错字、非实质措辞、配色、字体和已确认内容的局部排版不重新确认。

### 阶段 C：内容锁定与动态版式规划

用户确认后，记录 `content_plan_version` 和 `approval_status=confirmed`，再生成 `slide_content_lock` 和动态版式计划。每页必须说明：内容信号、版式家族、具体变体、视觉主角、组件、密度和版式理由。

正式生成前必须阅读：

- `references/dynamic-layout-system.md`
- `references/consulting-report-elements.md`
- `references/workflow-quality-gate.md`

复杂项目将内容稿和版式计划保存为 JSON，运行：

```bash
python scripts/validate_content_plan.py <content-plan.json> --require-confirmed
python scripts/validate_dynamic_plan.py <layout-plan.json> --require-confirmed
```

校验不通过时，先修订计划，不得进入 PPT 制作。

### 阶段 D：制作与质检

进入制作后完整读取并遵循当前 `Presentations` Skill。使用其当前指定实现，不调用本 Skill 内的历史 PptxGenJS 代码；在可写临时目录制作，只把最终 PPTX 放到用户指定或宿主规定的交付位置。

根据内容关系选版式，不得先挑模板：

- 阶段、里程碑、先后顺序 → 流程/路线图；
- 系统、平台、层级关系 → 架构分层/泳道；
- 比较、前后变化、优先级 → 对比/矩阵；
- 数据、规模、成效 → 数据证据页；
- 场景、旅程、办理过程 → 故事板/泳道；
- 条款、评分点、政策映射 → 证据映射表；
- 风险、保障、治理 → 控制闭环/风险措施矩阵。

结构关系优先用图示，不以卡片堆砌替代思考。封面、目录、分节、结束页只是页面角色，必须按会议目的选择变体，不得固定套用。

制作完成后必须渲染全部最终页，逐页全尺寸检查并运行溢出检查。无法完成渲染时不得声称交付完成，只能报告未完成项和阻塞原因。

## 3. 安铂视觉底线

默认采用商务风：深蓝结构色 `#004D85`，深蓝背景 `#003B66`，橙色焦点 `#F9904E`，浅蓝灰底 `#F8FAFC`，Slate 灰阶正文，16:9，Noto Sans SC 优先。

- 每页需要一个清晰视觉主角；图表、架构、流程、矩阵、截图或大数字均可。
- 商务/简约/扁平风保持安铂蓝橙；科技风和客户 VI 是明确例外，例外时不适用“每页必须蓝橙”的规则。
- 品牌识别可通过顶部条、侧栏、角标、结论条、页脚或进度条建立，按版式选择，不强制同一种页眉页脚。
- 禁止彩色 emoji、无来源数据、空白图片框、纯文字大段堆砌、连续三页同构卡片。
- 小型橙色结构线可作为品牌锚点；禁止无业务作用的通栏标题下划线。
- 图标仅在承担语义时使用；架构、数据、表格页不强塞装饰图标。

按需读取以下技术无关的视觉参考；具体对象和 API 仍以 `Presentations` 为准：

- `references/styles.md`：品牌令牌、简约/科技/扁平和客户 VI 边界；
- `references/color-chart.md`：色彩速查；
- `references/icons-images.md`：图标、图片、Logo 与来源边界；
- `references/consulting-report-elements.md`：从 CyberPPT 吸收的咨询报告页面表面、证据块、SO WHAT、微图表、矩阵、表格和 QA 规则；
- `references/diagrams.md`：关系、结构、流程的选型原则；
- `references/charts.md`：图表选型、口径和解读；
- `references/page-templates.md`：页面角色与构图参考，不是固定模板代码；
- `references/layout-blueprint-examples.md`：已确认内容到版式蓝图的示例。

## 4. 内容与视觉双门槛

每页必须同时达到：

| 门槛 | 要求 |
|---|---|
| 内容可信 | 有明确问题、解释、论据、结论；事实、行业假设和待补充信息边界清楚 |
| 视觉语义 | 版式能表达实际关系，阅读顺序、空间层级和视觉主角清楚 |
| 可编辑性 | 标题、正文、数字、图表标签、流程和结论优先使用原生对象 |
| 制作完成度 | 无溢出、遮挡、缺图、失衡、无意义留白或重复结构 |

## 5. 交付前质量门

交付前逐页检查：

- 内容是否仍与已确认版本一致；
- 结论标题是否可辩护，而非“项目背景/功能介绍”式栏目名；
- 图表有指标、单位、口径、标签和解读；架构有层级和连接关系；流程有阶段、输入输出和关键节点；高密度咨询页有证据块、侧栏洞察、SO WHAT、来源/caveat 或微图表等咨询报告元素；
- 普通内容页是否至少有主视觉和足够支撑信息，而不是几张漂浮卡片；
- 是否连续三页同骨架、是否出现两页以上纯文字页；
- 是否已渲染全部最终页、逐页全尺寸检查并运行溢出检查。

严重问题必须返工；不能把“文件能打开”视为交付完成。

## 6. 维护与验证

- skill 根目录只能保留一个 `SKILL.md`；备份放在 skill 根目录之外。
- 新增或修改工作流时，同步更新 `SKILL.md`、内容锁定、动态版式、质量门、校验脚本和 default prompt。
- 运行 `python <skill-creator>/scripts/quick_validate.py <skill-folder>` 验证结构。
- 不在本 Skill 中维护与 `Presentations` 并行的生成组件；载体 API 变化时只更新协同边界和视觉参考。
- 使用 `evals/evals.json` 中的代表性提示词复核：确认前停止、确认后生成、修改后重新确认、非安铂风格退出。
